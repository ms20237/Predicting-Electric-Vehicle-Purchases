# Predicting-Electric-Vehicle-Purchases

Solution for the Kaggle **Playground Series – Season 6, Episode 9: "Predicting Electric Vehicle Purchases"** competition. Binary classification task — predict the probability that a person will buy an EV (`Will_Buy_EV`), scored on **ROC-AUC**.

- **No missing values** and **no duplicate rows/ids** in either train or test.
- Target `Will_Buy_EV` arrives as `Yes`/`No` strings and is mapped to `1`/`0`.
- **Class imbalance**: 551,886 No (82.54%) vs 116,779 Yes (17.46%) — roughly a 4.73:1 ratio.
- **No train/test distribution shift**: a KS-test on every numeric column returned p > 0.05 for all of them, so engineered features built on train generalize safely to test.

### Buy rate by category (the real story)

- **`Subsidy_Available`**: Yes → **27.47%**, No → **0.58%** — by far the single strongest driver.
- **`Range_Anxiety_Level`**: Low → 18.90%, Medium → 4.17%, High → **0.14%** — purchase rate collapses almost to zero as anxiety rises.
- **`Home_Charging_Possible`**: Yes → 19.58%, No → 12.71%.
- **`City_Type`**: Rural 19.34% > Suburban 18.09% > Urban 16.11%.
- **`Current_Car_Type`**: SUV 18.10% > Hatchback 17.43% > Sedan 17.20% > Truck 15.64%.
- **`Gender`**: Female 17.76%, Other 17.37%, Male 17.23% — essentially no signal.

`Charging_Stations_Near_Home` and `Charging_Stations_Near_Work` correlate at **r = 0.51** (redundant signal), which is why they're compressed into combined features rather than used raw.

## 2. Feature engineering (`06_Feature_Engineering.ipynb`)

Original 15 columns → **29 columns** (21 numeric, 6 categorical), driven directly by the EDA findings above:

| Engineered feature | Rationale |
|---|---|
| `Home_Charging_bin`, `Subsidy_bin`, `Range_Anxiety_ord` | Numeric encodings of the strongest categorical signals |
| `Subsidy_x_EnvConcern`, `Subsidy_x_HomeCharging` | Interactions on the two strongest predictors |
| `EnvConcern_minus_RangeAnxiety` | Net "green readiness" score |
| `Total_Charging_Stations`, `Charging_Station_Ratio`, `Charging_Access_Score` | Compress the correlated (r=0.51), individually weak station counts |
| `Income_per_Age`, `Commute_per_Car` | Ratio features on `Annual_Income_USD` (the strongest numeric predictor) |
| `High_Env_Concern`, `Long_Commute`, `Age_Group` | Simple threshold/bin flags |

## 3. Cross-validation methodology (`07_Cross_Validation.ipynb`)

- **5-fold Stratified K-Fold**, `shuffle=True`, `random_state=42`.
- Fold assignment is generated once and cached to `artifacts/fold_ids.npy`, then reused by every model script (`02`–`05`). This guarantees all models are evaluated on identical splits, which is required for a leak-free ensemble in `08`.
- Verified stratification: every fold has n=133,733 with positive rate 0.1746, matching the overall rate exactly.

## 4. Model results

All models predict probabilities and are scored with ROC-AUC. Class imbalance handled via `class_weight="balanced"` (Logistic Regression), `scale_pos_weight`/`is_unbalance` (XGBoost/LightGBM), or `auto_class_weights="Balanced"` (CatBoost).

| Model | Fold 0 | Fold 1 | Fold 2 | Fold 3 | Fold 4 | **Mean CV AUC** | Std |
|---|---:|---:|---:|---:|---:|---:|---:|
| Logistic Regression (baseline) | 0.93681 | 0.93805 | 0.93924 | 0.93875 | 0.93815 | **0.93820** | ±0.00082 |
| CatBoost | 0.94022 | 0.94108 | 0.94252 | 0.94200 | 0.94149 | **0.94146** | ±0.00079 |
| XGBoost | 0.94019 | 0.94109 | 0.94242 | 0.94197 | 0.94137 | **0.94141** | ±0.00076 |
| LightGBM | 0.94032 | 0.94128 | 0.94265 | 0.94218 | 0.94149 | **0.94158** | ±0.00080 |

**LightGBM was the strongest single model** (OOF AUC 0.94157), narrowly ahead of CatBoost (0.94146) and XGBoost (0.94140), with all three gradient boosters landing within ~0.0002 of each other. Logistic Regression is a solid floor at 0.9382 but is clearly beaten by ~0.34 AUC points by every boosted-tree model.

| 1 | `Subsidy_Available` (0.443) | `Annual_Income_USD` (5071) | `Subsidy_x_EnvConcern` (26.90) |

Note: LightGBM's default importance is **split count**, not gain, so it surfaces high-cardinality numeric columns (income, commute) that get split on often but contribute less per split — this is a measurement artifact, not evidence that `Subsidy_Available` matters less for LightGBM. XGBoost and CatBoost (gain-based) agree closely: `Subsidy_Available` and its interaction with `Environmental_Concern_Level` dominate, consistent with the EDA buy-rate gap (27.47% vs 0.58%).

## 5. Ensemble (`08_Ensemble.ipynb`)

OOF predictions from all 4 models were combined using SLSQP-optimized, non-negative weights that sum to 1, maximizing OOF ROC-AUC (folds match `07`, so this is leak-free).

| Model | OOF AUC |
|---|---:|
| Logistic Regression | 0.93820 |
| CatBoost | 0.94146 |
| XGBoost | 0.94140 |
| **LightGBM** | **0.94157** |
| Simple average (4 models) | 0.94134 |
| **Optimized weighted ensemble** | **0.94135** |

Optimized weights: `baseline_logreg=0.246`, `catboost=0.254`, `xgboost=0.251`, `lightgbm=0.250` — nearly equal weighting, since the three boosters are highly correlated (same features, same folds) and add little diversity to blend against.

**Takeaway**: the ensemble (0.94135) did *not* beat the best single model (LightGBM, 0.94157). With near-identical, highly-correlated boosted-tree models trained on the same feature set, weighted averaging mostly just pulls the score toward the mean rather than adding lift — diversity (different feature subsets, different algorithms, or a stacked meta-model) would be needed to meaningfully beat the single best model here.

## 7. Reproducing this pipeline

```bash
pip install pandas numpy scikit-learn scipy seaborn matplotlib catboost xgboost lightgbm
```

Run notebooks in order — each stage writes artifacts the next stage depends on:

1. `01_EDA.ipynb` — dataset checks, distributions, signal analysis (writes `plots/`)
2. `06_Feature_Engineering.ipynb` — writes `dataset/train_fe.csv`, `dataset/test_fe.csv`
3. `07_Cross_Validation.ipynb` — writes `artifacts/fold_ids.npy` (shared folds)
4. `02_Baseline.ipynb`, `03_CatBoost.ipynb`, `04_XGBoost.ipynb`, `05_LightGBM.ipynb` — each writes `artifacts/oof_<model>.npy` and `artifacts/test_pred_<model>.csv`
5. `08_Ensemble.ipynb` — reads all available OOF/test predictions, optimizes ensemble weights, writes `submission.csv`

## 8. Possible next steps

- Hyperparameter tuning (Optuna) per model, since all three boosters were run with reasonable-but-unturned defaults.
- Try a stacked meta-model (e.g. logistic regression on OOF predictions) instead of a linear weighted blend — may extract more from model disagreement than a simplex-weighted average can.
- Add a diverse model (e.g. a neural net or a model trained on a different feature subset) to the ensemble, since the current 3 boosters are too correlated to gain much from blending.
- Since `Subsidy_Available` and `Range_Anxiety_Level` are so dominant, a deeper look at their interaction surface (e.g. target encoding, more granular anxiety buckets) may still have headroom.
